# Lithuanian and English speech routing

Research, 2026-11-04. This is a design to test, not a measured improvement or a change to the current app.

## Recommendation

Keep the chosen Lithuanian model for Lithuanian and mixed Lithuanian-English speech. Treat `deployinam endpointą į stagingą` as Lithuanian/mixed, not as a reason to switch. A sustained sentence such as “We will deploy the new endpoint tomorrow” is an English candidate. Preserve the speaker's words and endings; neither routing nor evaluation should assume a particular spelling of borrowed terms.

Test the existing native **Parakeet v3 path first** as a single resident LT/EN recognizer. NVIDIA says [Parakeet v3](https://huggingface.co/nvidia/parakeet-tdt-0.6b-v3) detects language without prompting and lists both Lithuanian and English. FluidAudio is already a dependency and the app's [Parakeet integration](../Parrot/Services/ParakeetTranscriber.swift#L1) uses it on the Neural Engine. This makes it a practical low-overhead candidate, not a proven efficiency or code-switch accuracy winner. Compare it on the same device and recordings with the selected Lithuanian model.

If its mixed recognition is inadequate, evaluate the existing multilingual WhisperKit `large-v3-v20240930_626MB` option, labeled Large V3 Turbo Compressed in the app ([TranscriptionEngine.swift:388](../Parrot/Services/TranscriptionEngine.swift#L388)). The [published model folder](https://huggingface.co/argmaxinc/whisperkit-coreml/tree/main/openai_whisper-large-v3-v20240930_626MB) is approximately 627 MB on disk, not a runtime RSS measurement. Also compare the locally configured multilingual Whisper large-v3 MLX, which the app labels “English” but is used with an English language setting. Only pursue specialist model switching if held-out accuracy gains justify measured delay and memory costs. An English-only checkpoint cannot serve as an LT detector or fallback.

If a Lithuanian-specialized model is materially better and switching pays for its cost, test a conservative, per-audio-side router. Use audio language evidence across complete voiced stretches, with an unknown state and hysteresis. A single English word, token, suffix, short reply, silence, or one uncertain window must not force a switch. A full English sentence is a candidate, not an unconditional switch. When uncertain, keep the current route; initially use the selected LT model. Allow an explicit language/model choice to override automatic routing.

## Feasibility and current behavior

Whisper's [language detection](https://github.com/openai/whisper/blob/main/whisper/decoding.py) scores the language tokens after the start token, producing a distribution for a supplied audio segment. It can accept already encoded audio features. This is a segment-level signal, not a word-level code-switch timeline, and its scores are not calibrated switch probabilities. Research on [token-level code-switch identification](https://aclanthology.org/2023.calcs-1.7/) uses a separately designed tokenizer and model; ordinary Whisper language detection does not supply that capability.

The installed `mlx-whisper` 0.4.3 has a `detect_language` path and can pass encoder features to it (`../.venv/lib/python3.12/site-packages/mlx_whisper/decoding.py:20`, `:537-563`, `:625-630`); the [MLX implementation](https://github.com/ml-explore/mlx-examples/blob/main/whisper/mlx_whisper/transcribe.py) also calls detection. Prototype exposing probabilities from an already loaded **multilingual** model and reusing the same chunk's encoded features for its transcription. This avoids a second encoder pass only when both operations use the same model, audio window and preprocessing; verify the actual API and profile it. An encoder from Ąžuolas cannot be reused as the encoder for the different large-v3 weights. Lithuanian fine-tuning may also change its LID behavior: evaluate it instead of assuming it remains multilingual or that its confidence is calibrated.

The live MLX path currently calls the selected model with the shared session language ([TranscriptionEngine.swift:1094](../Parrot/Services/TranscriptionEngine.swift#L1094)). Loading an MLX model clears WhisperKit and its detector ([TranscriptionEngine.swift:201](../Parrot/Services/TranscriptionEngine.swift#L201), [detector:282](../Parrot/Services/TranscriptionEngine.swift#L282)); `checkLanguage` uses that WhisperKit detector ([line 1365](../Parrot/Services/TranscriptionEngine.swift#L1365)). The existing per-side router is specifically for Parakeet versus unsupported-language Whisper fallback, not LT versus EN MLX routing ([LanguageRouter.swift:26](../Parrot/Services/LanguageRouter.swift#L26)); its probe uses energy-gated audio ([TranscriptionEngine.swift:557](../Parrot/Services/TranscriptionEngine.swift#L557)), whereas the live decode also has a Silero voice gate. Do not treat the existing 0.8 and 30-second rules as validated LT/EN thresholds.

Current Parakeet Auto does **not** exercise a detector-free single-model path: it loads Whisper Tiny ([TranscriptionEngine.swift:217](../Parrot/Services/TranscriptionEngine.swift#L217)), holds undecided sides and may fall back to Whisper; Tiny's LT failures were observed locally ([PERFORMANCE.md:288](PERFORMANCE.md#L288)). For a controlled, local LT/EN-only evaluation, call the existing Parakeet transcriber directly with a nil language hint, bypassing that unrelated third-language gate in an isolated experiment, and separately test the actual app's Auto and pinned LT/EN paths. The hint is a script filter ([ParakeetTranscriber.swift:30](../Parrot/Services/ParakeetTranscriber.swift#L30)); both LT and EN use Latin script, but identical mixed-speech output is not established. This experimental bypass assumes the test set contains only LT/EN and does not authorize removing the third-language protection from production.

The helper serializes requests and bounds the queue ([HostMLXService.swift:13](../HostHelper/HostMLXService.swift#L13)); its worker holds one model path and clears the model and MLX cache on a path change ([mlx_worker.py:38](../HostHelper/Resources/mlx_worker.py#L38)). Thus frequent model switching currently reloads weights and can stall both sides. Loading a separate multilingual LID model solely to monitor the Lithuanian model adds memory and inference; it is not free reuse. A multi-resident design would need a changed worker, bounded memory policy and measurement, including macOS unified-memory pressure. Keep the active model resident by default; compare cold switching, keeping both loaded, and a single multilingual model. Preload the other model only if measured RAM and switching delay justify it. On a load failure, pressure or queue saturation, keep the working route and retained audio, report the problem, and do not silently discard speech.

The [Ąžuolas model card](https://huggingface.co/akisviete/azuolas-whisper-lt) and [Paprika MLX card](https://huggingface.co/internetworks/paprika-whisper-lt-v3-mlx) describe Lithuanian ASR, but do not establish preservation of LT-inflected English terms in these calls. Local synthetic checks covered three Lithuanian sentences and one English sample, not mixed conversations; related exploratory measurements are in [PERFORMANCE.md](PERFORMANCE.md#L283). Spoken Lithuanian research distinguishes borrowings and code mixing ([corpus study](https://journals.vu.lt/lietuviu-kalba/en/article/view/22518)); a [study of English loanwords](https://arrow.tudublin.ie/itbj/vol13/iss1/4/) also observes English and Lithuanian suffix merging. Neither English-looking stems nor Lithuanian-looking endings alone identify an utterance's route.

## Candidate switching experiment

The following values are **proposed starting points, unvalidated**, not production settings or claims of accuracy:

1. Maintain separate Me/Them audio buffers and route state. Collect VAD-confirmed speech with original timing; do not concatenate distant speech into a misleading continuous utterance. Respect echo suppression and overlapping speakers. No decision on silence, very short speech or detector failure.
2. At utterance boundaries, test roughly 5–10 seconds of voiced speech when available; for longer turns, sample every 5 seconds of new voiced audio. Evaluate non-overlapping windows for confirmation, rather than counting an overlapping sliding window twice. Include an unknown result if less than 3 seconds of usable speech, if another language wins, or if the LT/EN evidence is close. These window lengths and overlap policy must be tuned on real calls.
3. For an LT-to-EN candidate, try two consecutive independent windows with English the overall top language, score at least 0.8 and a margin of at least 0.3 over Lithuanian; require at least 8 seconds of combined voiced evidence. Reverse the criterion for EN-to-LT. These are raw-score heuristics, not probabilities of correctness. Unknown leaves the route unchanged; contrary evidence clears the pending candidate. A confidently identified third language also goes to an explicit unknown/manual or validated multilingual fallback, not forced into LT or EN.
4. Optionally use a sufficiently long transcript as a **veto or corroborating signal**, never a token vote or a sole decision. Transcript and audio scores from the same model are correlated, and a model can normalize or mishear the English stem. Do not infer exact word boundaries from a segment score. The whole-text [fastText classifier](https://fasttext.cc/docs/en/language-identification.html) is cheap in the local trial but its LT result for a mixed text does not reveal its English words ([PERFORMANCE.md:289](PERFORMANCE.md#L289)). Apple likewise describes `NLLanguageRecognizer` as detecting a text's [dominant language](https://developer.apple.com/documentation/naturallanguage/nllanguagerecognizer/languagehypotheseswithmaximum%3A). Neither proves when spoken language changed.
5. Commit a switch at a safe chunk boundary and retain a bounded timestamped audio window while loading. Reprocess the affected interval only after the new model is ready; replace provisional output by stable segment identity and preserve order without duplicates. Limit any cooldown so a real reverse switch remains detectable. Per-side decisions must not overwrite the other side's route. If two sides need different models, assess serialization, memory and latency before enabling automatic switching.

These rules are deliberately biased against false switches; they will delay or miss brief English turns. Thresholds must be selected from held-out conversations using the relative cost of false switches, missed switches and delay. Never report synthetic tests as proof that this policy works on humans.

## Alternatives and validation

- [SpeechBrain VoxLingua107](https://huggingface.co/speechbrain/lang-id-voxlingua107-ecapa) supports LT and EN, but the local exploratory run used 619 MB RSS including its Python process and gave unreliable mixed, silence and short-word results ([PERFORMANCE.md:290](PERFORMANCE.md#L290)). Its warm timing on synthetic clips does not establish live accuracy. A smaller dedicated audio LID is an alternative only if its documented label set includes Lithuanian and English and its measured deployment cost and mixed-call errors beat reuse; no such candidate is established here. Tiny Whisper's local LT failures ([PERFORMANCE.md:288](PERFORMANCE.md#L288)) rule it out as an automatic router on current evidence.
- The official [Silero classifier list](https://github.com/snakers4/silero-vad/wiki/Version-history-and-Available-Models) lists `silero_lang_detector_95` at 4.7 million parameters and marks language detection deprecated since 2023-04-27. The v3.1 [label dictionary](https://github.com/snakers4/silero-vad/blob/v3.1/files/lang_dict_95.json) contains English but no Lithuanian, so that release cannot identify LT as its own class and is unsuitable for this decision. Its [loader](https://github.com/snakers4/silero-vad/blob/v3.1/hubconf.py) offers ONNX and JIT downloads, and the repository's [license](https://github.com/snakers4/silero-vad/blob/v3.1/LICENSE) is MIT; neither establishes current artifact availability, mixed-speech accuracy, or the total runtime footprint. Check the exact model version and labels before considering any later variant. Existing Silero VAD does not itself provide this classifier.
- Apple Speech recognizers are created for one locale and [locale availability is not guaranteed](https://developer.apple.com/documentation/speech/sfspeechrecognizer/supportedlocales%28%29). [Apple's Speech API](https://developer.apple.com/documentation/speech/sfspeechrecognizer) therefore is not evidence of a free mixed-LT/EN detector. Check on-device availability and privacy before evaluating it.
- Capture and label a local, consented, speaker-disjoint set of real calls: pure LT, pure EN, LT with English technical words and inflections, full turns switching both ways, short acknowledgments, silence, overlap, varied accents, microphone and remote audio. Include unseen speakers and terms; keep audio local. Annotate utterance and switch times plus spoken-word references, including acceptable spellings separately, without silently normalizing away missing words.
- Compare direct Parakeet v3, its current Auto and pinned paths, WhisperKit compressed turbo, fixed Ąžuolas, fixed Paprika, multilingual large-v3 MLX, and the candidate router on the same clips. Report LT, EN and mixed word error rates, technical-term and suffix preservation, false switches per hour, missed switches, time to correct route, unknown rate, and dropped/duplicated segments. Include switch boundaries and short English turns; score both sides separately. Tune on a development set, freeze the rule, then evaluate held-out speakers and calls.
- Measure full app plus helper: cold and warm load, switch time, first and p50/p95 segment latency, real-time factor, CPU and GPU time, peak/steady process and system memory, memory pressure and queue backlog for both sides. Compare one resident model, swapping one at a time and both resident; include the detector's preprocessing and any repeated encoder pass. Test long calls, sleep/wake, errors and rapid alternation. Use the same hardware, settings and clips, and report energy separately if measured. Enable automatic routing only if held-out accuracy and latency satisfy agreed targets; until then manual selection remains the reliable option.
